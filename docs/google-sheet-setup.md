# 結帳串接 Google Sheet 安裝說明

網站送出的訂單會透過 Google Apps Script（GAS）寫進你的 Google 試算表。整個設定約 5 分鐘，只需要做一次。

## 架構

```
網站結帳表單 ──POST(JSON)──▶ GAS 網頁應用程式 ──▶ Google 試算表
                                │                    ├ 訂單（一筆訂單一列）
                                │                    ├ 訂單明細（一個商品一列）
                                └─▶ Email 通知（選用）  └ 商品（價目表，可直接改價／下架）
```

- 金額一律由 GAS 依「商品」工作表重新計算，前端傳來的價格不會被採用。
- 訂單編號由 GAS 產生，格式 `DD-日期-流水號`，例如 `DD-20261116-001`，每天從 001 開始。
- 同一次結帳重複按送出，只會建立一筆訂單。
- `index.html` 裡的 `ORDER_API_URL` 留空時，網站維持原本的「示範結帳」，不會送出任何資料。

## 步驟一：建立試算表與程式

1. 到 Google 雲端硬碟，新增一份空白試算表，例如命名為「豆豆貼訂單」。
2. 在試算表上方選單點 **擴充功能 → Apps Script**。
3. 刪掉編輯器裡原本的內容，貼上本 repo 的 `gas/Code.gs` 全部內容，按儲存。
4. 左上方函式選單選 `setup`，按 **執行**。
   - 第一次執行會要求授權：選你的帳號 → 「進階」→「前往（不安全）」→ 允許。這是你自己的程式，所以 Google 會顯示這個提醒。
5. 回到試算表，會看到「訂單」「訂單明細」「商品」三個工作表，上方也會多出「豆豆貼」選單。如果沒看到選單，重新整理頁面。

## 步驟二：部署成網頁應用程式

1. 在 Apps Script 編輯器右上角點 **部署 → 新增部署作業**。
2. 類型（齒輪圖示）選 **網頁應用程式**。
3. 設定：
   - 執行身分：**我**
   - 具有存取權的使用者：**所有人**（顧客不需要登入 Google 才能下單）
4. 按「部署」，複製產生的 **網頁應用程式網址**，結尾是 `/exec`。

## 步驟三：把網址填進網站

打開 `index.html`，找到這一行：

```js
const ORDER_API_URL='';
```

把網址貼進引號裡：

```js
const ORDER_API_URL='https://script.google.com/macros/s/xxxxxxxx/exec';
```

存檔並推到 `main`。也可以直接把網址給 Claude，請它幫你填好。

## 步驟四：測試

1. 在試算表選單點 **豆豆貼 → 建立一筆測試訂單**，「訂單」工作表應出現一筆 `DD-…-001`。
2. 到網站加入商品並結帳，成功後畫面會顯示 GAS 產生的訂單編號，試算表會同步新增一列。
3. 測試完可以直接刪除測試資料列。

## 日常使用

| 想做的事 | 怎麼做 |
| --- | --- |
| 更新訂單狀態 | 「訂單」工作表的「狀態」欄有下拉選單：新訂單、製作中、可取餐、已出貨、已完成、已取消 |
| 改價格 | 直接改「商品」工作表的「單價」，網站下一筆訂單就會用新價格計算。網站上顯示的價格要另外改 `index.html` |
| 暫停販售某商品 | 取消勾選「商品」工作表的「販售中」，顧客送出含此商品的訂單會收到提示 |
| 新訂單 Email 通知 | 選單 **豆豆貼 → 設定通知 Email** |
| 看今天的營業額 | 選單 **豆豆貼 → 今日訂單摘要** |

## 修改 GAS 程式後

改完 `Code.gs` 後必須重新部署，網站才會用到新版本：

**部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**

這樣網址不會改變。如果改用「新增部署作業」，會產生新網址，需要重新填進 `index.html`。

## 注意事項

- 試算表裡有顧客姓名與電話，請勿把試算表分享給不相關的人。
- 網頁應用程式網址等於訂單入口，公開在網站上是正常的。GAS 會驗證每個欄位，也有防機器人的隱藏欄位。
- GAS 免費版有每日配額，一般個人帳號約 100 封 Email、數萬次執行，小店使用綽綽有餘。
